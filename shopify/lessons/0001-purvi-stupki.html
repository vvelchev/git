Картата: какво всъщност прави един Shopify developer

Shopify е платформа за онлайн магазини. Хостингът, плащанията, базата данни и админ панелът са на Shopify. Ти пишеш кода, който определя как изглежда магазинът и какво още може. Има три основни посоки:

Започваме тукThemesТеми

Визията на магазина. Liquid + HTML + CSS + JS. Най-бързият път до видим резултат.

AppsПриложения

Нова функционалност: интеграции, автоматизации, админ екрани. React + GraphQL Admin API.

HeadlessHydrogen

Изцяло собствен frontend върху Storefront API. За големи проекти с нужда от пълен контрол.

Този урок е за темите. Там е повечето клиентска работа и там се учи Liquid, който ще ти трябва и в другите две посоки.

01

Подготви средата

Трябват ти четири неща:

  1. Node.js (LTS версия, 20 или по-нова) от nodejs.org. Shopify CLI работи върху него.
  2. Git от git-scm.com. Ще пазиш историята на темата си.
  3. VS Code с разширението Shopify Liquid. Дава оцветяване, автодовършване и проверка на грешки в реално време.
  4. Shopify CLI, главният инструмент. Инсталира се с npm:
Терминал
# инсталира Shopify CLI глобално
npm install -g @shopify/cli@latest

# проверка, че всичко е наред
node -v
shopify version
Windows: ако PowerShell откаже да пусне shopify заради execution policy, използвай Git Bash или терминала във VS Code.
02

Направи си development магазин

Никога не експериментирай върху истински магазин. За целта Shopify дава безплатни development stores: пълноценни магазини без месечна такса, които не приемат реални плащания.

  1. Регистрирай безплатен Partner акаунт на shopify.com/partners.
  2. От dashboard-а избери Stores → Create development store.
  3. Отметни опцията за тестови данни (sample data), за да имаш продукти и колекции веднага.
  4. Запиши адреса. Той изглежда така: moyat-test.myshopify.com.

Dev магазините са защитени с парола. Ще я намериш в админа под Online Store → Preferences. CLI-ят може да я поиска при първото пускане.

Тестови поръчки: в dev магазин включи Bogus Gateway или Shopify Payments в тестов режим и пробвай целия checkout без реални пари.
03

Първата ти тема на локален сървър

shopify theme init създава нова тема от официален стартов шаблон. shopify theme dev я качва като скрита development тема и пуска локален preview, който се обновява при всяко запазване на файл.

Терминал
# създава папка moyata-tema със стартова тема
shopify theme init moyata-tema
cd moyata-tema

# пуска live preview срещу твоя dev магазин
shopify theme dev --store moyat-test

Първия път CLI-ят ще отвори браузъра за вход в Shopify. След това в терминала ще видиш:

Какво ще видиш
Preview your theme
  • http://127.0.0.1:9292

Customize your theme at the theme editor
  • https://moyat-test.myshopify.com/admin/themes/.../editor

Share your theme preview
  • https://moyat-test.myshopify.com/?preview_theme_id=...

Отвори http://127.0.0.1:9292, промени някакъв текст в кода, запази и гледай как страницата се обновява сама. Това е основният ти работен цикъл.

Кой шаблон? Новите версии на CLI по подразбиране вземат минималния Skeleton theme: малко код, лесен за разбиране. Ако искаш да разгледаш пълна, production тема, клонирай Dawn: shopify theme init uchebna --clone-url https://github.com/Shopify/dawn
04

Анатомия на една тема

Всяка Online Store 2.0 тема има едни и същи папки. Shopify очаква точно тези имена, затова не ги преименувай.

layout/
theme.liquid е рамката на всяка страница: <head>, header, footer. Съдържанието се вмъква чрез {{ content_for_layout }}.
templates/
По един файл за всеки тип страница: index.json, product.json, collection.json… JSON файлът изрежда кои секции и в какъв ред.
sections/
Големите, преместваеми блокове на страницата. Всяка секция има {% schema %} с настройки за Theme Editor-а.
blocks/
Theme blocks: по-малки парчета, които търговецът добавя вътре в секциите.
snippets/
Преизползваем код без настройки. Включва се с {% render 'ime' %}.
assets/
CSS, JS, картинки, шрифтове. Линк към тях с филтъра asset_url.
config/
settings_schema.json описва глобалните настройки (цветове, шрифтове). settings_data.json пази избраните стойности.
locales/
Преводи. bg.json + {{ 'kluch' | t }} = текстове на български.
templates/index.json (опростен)
{
  "sections": {
    "hero":     { "type": "image-banner" },
    "featured": { "type": "featured-collection" }
  },
  "order": ["hero", "featured"]
}

Когато търговецът мести секции в редактора, Shopify пренаписва точно този JSON. Ти пишеш секциите, търговецът ги подрежда.

05

Liquid за 10 минути

Liquid е шаблонният език на Shopify. Сървърът го изпълнява и браузърът получава чист HTML. Има само три вида синтаксис:

{{ }}

Output. Извежда стойност: {{ product.title }}

{% %}

Tag. Логика: if, for, render, schema. Сам по себе си не извежда нищо.

|

Filter. Преобразува стойност: {{ product.price | money }}

Обекти

Данните идват от глобални обекти. Най-честите: shop, product, collection, cart, customer, settings, request. Кои са налични зависи от страницата: product съществува на продуктова страница, cart навсякъде.

Пример: първите 4 продукта от колекция

sections/collection-grid.liquid
<ul class="grid">
  {% for product in collection.products limit: 4 %}
    <li>
      <a href="{{ product.url }}">
        {{ product.featured_image | image_url: width: 400 | image_tag }}
        <h3>{{ product.title | escape }}</h3>
        <p>{{ product.price | money }}</p>
      </a>
      {% unless product.available %}
        <span class="badge">Изчерпан</span>
      {% endunless %}
    </li>
  {% else %}
    <li>Няма продукти в тази колекция.</li>
  {% endfor %}
</ul>

Два непознати тага в примера

{% else %} вътре във for. Тук няма if. Liquid позволява else директно в цикъла и то се изпълнява само ако колекцията е празна, т.е. цикълът не е минал нито веднъж. Същото с if би изглеждало така:

Еквивалент с if
{% if collection.products.size > 0 %}
  {% for product in collection.products limit: 4 %}
    …
  {% endfor %}
{% else %}
  <li>Няма продукти в тази колекция.</li>
{% endif %}

{% unless %} е обратното на if и означава „ако не“. {% unless product.available %} е същото като {% if product.available == false %}. Баджът „Изчерпан“ се показва, когато продуктът не е наличен.

Цените са в центове. product.price връща 4999 за 49,99 €. Затова винаги минавай през | money, който форматира по валутата на магазина.
06

Направи своя първа секция

Тук всичко се събира: HTML + Liquid + schema, която дава на търговеца бутони в Theme Editor-а. Създай файл sections/hello-banner.liquid:

sections/hello-banner.liquid
<section class="hello-banner" style="background: {{ section.settings.bg }};">
  <h2>{{ section.settings.heading | escape }}</h2>

  {% if section.settings.show_count %}
    <p>В магазина има {{ collections.all.products_count }} продукта.</p>
  {% endif %}
</section>

{% stylesheet %}
  .hello-banner { padding: 48px 24px; text-align: center; }
{% endstylesheet %}

{% schema %}
{
  "name": "Hello банер",
  "settings": [
    { "type": "text",     "id": "heading",    "label": "Заглавие", "default": "Здравей, Shopify!" },
    { "type": "color",    "id": "bg",         "label": "Фон",      "default": "#eef3ee" },
    { "type": "checkbox", "id": "show_count", "label": "Покажи броя продукти", "default": true }
  ],
  "presets": [{ "name": "Hello банер" }]
}
{% endschema %}
  1. Запази файла, докато shopify theme dev работи.
  2. Отвори линка за theme editor от терминала.
  3. Натисни Add section и избери „Hello банер“.
  4. Смени заглавието и цвета отдясно. Това са твоите settings.

section.settings.heading чете стойността, която търговецът е въвел. presets е причината секцията да се появи в списъка Add section. Без него няма да я намериш там.

Предизвикателство: добави настройка "type": "collection" и покажи 3 продукта от избраната колекция с цикъла от стъпка 5.
07

Работен процес, който не чупи live магазина

В един магазин има една live тема, която клиентите виждат, и много unpublished теми. Правилото е просто: работиш локално и качваш в unpublished тема. Публикуваш едва след преглед.

Командите, които ще ползваш всеки ден
# списък на темите в магазина с техните ID-та
shopify theme list --store moyat-test

# сваля тема от магазина (напр. промени от редактора)
shopify theme pull --theme 123456789

# проверява кода за грешки и лоши практики
shopify theme check

# качва като НОВА скрита тема, live не се пипа
shopify theme push --unpublished

# качва в конкретна тема и дава preview линк за клиента
shopify theme push --theme 123456789
shopify theme share

# публикува, само когато си сигурен
shopify theme publish --theme 123456789

Git от първия ден

Терминал
git init
git add .
git commit -m "Първоначална тема"

След това можеш да свържеш GitHub repo директно с магазина: Online Store → Themes → Add theme → Connect from GitHub. Всеки push в клона обновява свързаната тема автоматично.

Внимание: търговецът също променя темата през редактора и тези промени отиват в templates/*.json и config/settings_data.json. Преди push направи pull, иначе ще изтриеш неговата работа.
